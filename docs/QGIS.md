# Connecting QGIS / UMEP

This is a diagnostic integration, not a completed scientific adapter. Use the Python interpreter shipped with your QGIS installation rather than installing QGIS Python modules into the application's virtual environment.

1. Install QGIS and the **UMEP for Processing** plugin using the official supported installation instructions.
2. Set `UMEP_QGIS_PYTHON` to its Python executable. Optionally set `QGIS_PREFIX_PATH` if required by that installation.
3. Set `UMEP_PLUGIN_DIR` to the parent directory containing the `processing_umep` package. Only use a trusted installed plugin: loading it executes Python code.
4. Restart the API and worker after changes. The API caches capability diagnostics for its lifetime.
5. Inspect `/api/capabilities`, or run `QT_QPA_PLATFORM=offscreen /usr/bin/python3 backend/qgis_probe.py` with writable `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, and `XDG_CACHE_HOME`.

The application automatically uses `.data/qgis-*` writable XDG directories for probes. On this machine, QGIS 3.40.6 and standard processing providers are available, UMEP is absent, and PDAL is absent. The installed provider probe has no UMEP algorithms. No scientific output has been produced or validated.

The probe obtains parameter names/descriptions/types from the installed registry; it does not invent a SOLWEIG command. Before enabling execution, implement and test a versioned mapping from managed rasters/weather/grid to that provider's required parameters. Automate wall geometry and sky-view factor prerequisites, engine-specific weather conversion, progress capture, and actual output discovery. Verify a small scientific run against official documented examples. Use isolated subprocesses and register only outputs actually generated by the engine.
